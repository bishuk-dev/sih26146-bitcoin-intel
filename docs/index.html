How this project works

We take messy transaction and network records (like IPs and wallets), connect them together, and use machine learning to find suspicious patterns. Finally, we show an investigator exactly why an entity was flagged.

Rule for everyone: You don't need to learn the whole field. Learn the specific parts you need to build your module, then test it.

02 · HOW THE DATA CHANGES

From CSV to alerts

1. Raw RowsM1 loads CSVs of transactions and network logs.
2. Clean TablesM1 cleans missing values, fixes types, and generates our dataset.
3. GraphM2 turns those rows into connected dots (nodes and edges) using CIO.
4. FeaturesM2 measures behavior for each wallet (e.g., Degree, Burstiness).
5. AlertsM3 runs models to score suspiciousness, and M4 ranks them into alerts for M5's dashboard.
03 · THREE TOOLS, THREE QUESTIONS

The core approach

“Does this match known suspicious patterns?”XGBoost learns from our synthetic training data.
“Is this statistically unusual?”Isolation Forest provides a secondary anomaly signal without needing labels.
“Who is connected to them?”The graph and DBSCAN show the network context around the entity.
04 · ML DECISION

Our Machine Learning Stack

official team plan
PRIMARY
XGBoost

A supervised model. We train it on synthetic ground-truth labels. It's fast, CPU-friendly, and works well with SHAP explanations.

SECONDARY
Isolation Forest

An unsupervised model. It checks if behavior is statistically unusual compared to everyone else.

SUPPORTING
DBSCAN + Graph

Groups similar entities (clustering) to give investigators context about the neighborhood around an alert.

Note: We use synthetic labels to train XGBoost, but we NEVER pass the label as a feature. We evaluate on different scenarios to ensure the model actually learned patterns, not just memorized numbers.

EVALUATION RULE

Ground truth is for training AND testing — but never as a feature.

X = df[FEATURE_COLUMNS]y = df["ground_truth_anomalous"]model.fit(X_train, y_train)metrics(y_test, predictions)

The test label is not shown to the model. It only lets us measure how well our detector did.

DO NOT CHEAT YOURSELF

Red flags in your own experiment

  • Random row split only.
  • Ground-truth column accidentally included in X.
  • Training and test generated with exactly the same tiny rule.
  • Accuracy shown without false positives.
  • “Confidence 97%” without saying what it means.

JUDGE QUESTIONS

Prepare short, honest answers.

Why XGBoost?

It's CPU-friendly, handles structured features well, and gives straightforward SHAP explanations.

Why Isolation Forest?

It gives an independent unsupervised anomaly signal without relying on training labels.

Why synthetic data?

The PS requires it. We evaluate on distinct generator distributions so the model learns concepts, not just fixed ranges.

Does an alert prove a crime?

No. It is an investigative lead based on behavioral anomalies.

Why a graph?

Because the real value is understanding who an entity is connected to, not just what they did in one transaction.
